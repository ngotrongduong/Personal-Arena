## Spec

### 1. Schema description — `Trainer/schemas/survivor_v<N>.json`

One file per observation schema version; v4 is the only real one today. The format:

```json
{
  "schema_version": 4,
  "observation": [
    {"name": "self",      "repeat": 1,  "fields": ["hp_fraction", "max_hp", "...64 names"]},
    {"name": "inventory", "repeat": 64, "fields": ["level"]},
    {"name": "offers",    "repeat": 4,  "fields": ["item_00", "...", "item_63", "next_level", "present"]},
    {"name": "rays",      "repeat": 72, "fields": ["...25 names"]},
    {"name": "density",   "repeat": 24, "fields": ["...3 channel names"]}
  ],
  "actions": [
    {"name": "move", "size": 9}, {"name": "skill", "size": 5}, {"name": "pick", "size": 5}
  ]
}
```

- Segments are laid out in order, and each segment is `repeat × len(fields)` values, repeat-major
  (all fields of element 0, then element 1, ...). Read `SurvivorObservation.cs` and name every field
  after what it holds.
  - Unused or zero slots are named `reserved_<k>`, for example self index 13 and unused build-stat
    slots. Density order must match the code; if the code is sector-major instead, describe it
    as it really is.
  - Total size must be 2264.
- A later schema may only **grow**: segments and fields can be appended or inserted, repeats can
  grow, action branches and branch sizes can grow. Fields and segments are matched by **name**.
  Removing or renaming a used field is not an upgrade; the tool refuses it. Filling a `reserved_<k>`
  slot with a real meaning does **not** change the schema version (the weights already exist).
- `arena_trainer.py` adds:
  - `SCHEMAS_DIR`;
  - `schema_path(version) -> Path`;
  - `load_schema(version) -> dict`, which validates names are unique within a segment, sizes are
    positive and totals are consistent, and raises `ValueError` otherwise;
  - `observation_size(schema)`.
  - `SCHEMA_VERSION` (4) must have a file (pytest).
- **C# check** (`SurvivorObservationSchemaTests`):
  - Find the repo root by walking up from the test assembly folder to the folder that holds
    `AGENTS.md`, then read `Trainer/schemas/survivor_v4.json` with `System.Text.Json`.
  - Check:
    - total = `SurvivorObservation.Size`;
    - `schema_version` = `SurvivorObservation.SchemaVersion`;
    - segment offsets = `SelfOffset` / `InventoryOffset` / `OffersOffset` / `RaysOffset` / `DensityOffset`;
    - the rays field count = `RayStride`;
    - the action sizes = `SurvivorInput.MoveBranchSize` / `SkillBranchSize` / `PickBranchSize`.

### 2. `Trainer/brain_upgrade.py`

#### 2.1 Library

```python
def column_map(old_schema: dict, new_schema: dict) -> list[int]:
    """new column index for every old observation index; raises UpgradeError if not a pure growth."""

def action_map(old_schema, new_schema) -> list[tuple[int, int]]:
    """per old branch: (new branch index, old size); old actions keep their positions at the start."""

def upgrade_state(checkpoint: dict, old_schema, new_schema, seed=0) -> dict:
    """Return a new checkpoint dict (torch tensors) for the new schema."""

def upgrade_run(runs_dir: Path, source_run: str, behavior: str, new_run: str,
                old_version: int, new_version: int) -> Path:
    """Create runs_dir/new_run from the newest checkpoint of source_run; returns the new behavior dir."""
```

#### 2.2 What `upgrade_state` does (mlagents 1.1.0 checkpoint keys)

Real key names are in `Warrior/checkpoint.pt`: `Policy`, `global_step`,
`Optimizer:value_optimizer` (Adam) and `Optimizer:critic`.

- **Input layer:** `Policy` and `Optimizer:critic`, key `network_body._body_endoder.seq_layers.0.weight`
  with shape `[hidden, obs]`.
  - Build the new matrix `[hidden, new_obs]` with zeros.
  - Copy each old column to `column_map[old]`.
  - Keep the bias and every other layer unchanged.
- **Actions:** `Policy`, key `action_model._discrete_distribution.branches.<i>.weight/bias`.
  - Old rows keep their positions; appended action rows get weights `N(0, 0.01)` and bias equal to
    the branch's minimum old bias.
  - A new branch gets `N(0, 0.01)` weights and zero bias.
  - Update `discrete_act_size_vector` to the new sizes.
  - With no new actions the branches are copied unchanged.
- **Adam state:** drop `Optimizer:value_optimizer` (the reset). mlagents then starts a fresh Adam
  for all parameters; confirm this in the test (§2.4).
- **Step:** keep `global_step`, so step numbers continue. The new run's first brain is
  `<Behavior>-<step>.pt`.
- **Refusals:**
  - an obs width in the checkpoint that does not equal the old schema size;
  - an LSTM or normalizer present;
  - a pure-growth violation.

#### 2.3 What `upgrade_run` writes (never touching the source run)

- Output:
  - `new_run/<Behavior>/checkpoint.pt`, plus the same content as `<Behavior>-<step>.pt`, so
    `plan_run`, `export_brain` and `champion` treat it like any run;
  - `new_run/schema_version.txt` (new version), with `arena_trainer.write_schema_version` or an
    equivalent taking a version;
  - `new_run/upgraded_from.json`: `{source_run, source_step, old_schema, new_schema, created_at}`.
- **Curriculum state (important):**
  - Copy `source_run/run_logs/training_status.json` to `new_run/run_logs/training_status.json`,
    keeping the `metadata` block and every `lesson_num`.
  - **Remove every behavior's `"checkpoints"` list.** Otherwise mlagents' `keep_checkpoints` cleanup
    would later delete files of the *source* run, because the paths point there.
  - When the source has no status file, write none.
- Refuse when `new_run` already exists.
- The source run must be byte-for-byte untouched; pytest checks this with file hashes.

### 3. Build-conditioned training and review curriculum

#### 3.1 Episode kinds — `SurvivorEnvFactory`

```csharp
public enum SurvivorEpisodeKind { New, Review, Hard }
public sealed class SurvivorEpisode { public SurvivorEpisodeKind Kind; public CharacterBuild Build; public int OpeningRing; }
public static SurvivorEpisode CreateEpisode(Rng rng, float tierMin, float tierMax, float buildLevelMax,
    float ownBuildShare, float reviewShare, float hardShare, CharacterBuild ownBuild);
```

- Draw `r = rng.NextFloat()` **only when** `reviewShare + hardShare > 0`. With both at 0 the result
  must be exactly `CreateBuild(...)` with the same RNG sequence: today's runs must not change.
- The three kinds:
  - `r < hardShare` → **Hard**: tier `Tier(tierMax + 1)` (clamped to 10), a random build up to
    `buildLevelMax` (as `BuildRandomizer.Random` does), `OpeningRing = 16`.
  - `r < hardShare + reviewShare` → **Review**: `new CharacterBuild { Tier = 1 }` (the M4A
    baseline), no ring.
  - otherwise → **New**: `CreateBuild(...)` exactly as today, no ring.
- Clamp shares to [0, 1]. If the sum is above 1, scale both down so it is 1.

#### 3.2 Opening ring (Core)

- `SurvivorConfig.OpeningRing` is an int, default 0.
- On reset, when it is above 0, the sim spawns that many enemies of the first (weakest) regular type
  evenly on a 6 m circle around the hero at t = 0. The tier scaling applies as usual. Positions stay
  inside the map; skip a spot that is inside an obstacle.
- The ring uses **no RNG** (fixed angles), so with `OpeningRing = 0` every seed plays bit-for-bit like
  today. Existing determinism tests must stay green.
- CoreTests:
  - ring count and radius;
  - ring 0 leaves the enemy count at t = 0 unchanged;
  - the same seed gives the same result.

#### 3.3 `HeroAgent`

- Read `review_share` and `hard_share` (default 0) and use `CreateEpisode`.
- Set `Config.Build` and `Config.OpeningRing` from it.
- At episode end, record `Arena/Episode/SurvivedNew|Review|Hard` (seconds survived) with the stats
  recorder, following the existing `Arena/...` stat code in `HeroAgent`. The owner's charts can then
  tell the kinds apart.

#### 3.4 Config `warrior_survivor_ppo.yaml`

- `run_seconds` is unchanged: same names, values and thresholds. The live run is mid-curriculum.
- `build_level_max`: a curriculum measured by **progress** (step / max_steps, max_steps 1e8):
  - `blank` 0 until 0.22;
  - `light` 10 until 0.30;
  - `medium` 25 until 0.40;
  - `full` 50.
  - Use `min_lesson_length: 200` and `behavior: Warrior`.
- `tier_max`: progress curriculum:
  - `tier-1` 1 until 0.45;
  - `tier-3` 3 until 0.60;
  - `tier-6` 6 until 0.75;
  - `tier-10` 10.
  - `tier_min` stays 1.
- `review_share: 0.2`, `hard_share: 0.1`; `own_build_share: 0.0` (M5).
- Write a short comment explaining why progress and not reward: a harder build or tier must not

### 4. Training service: automatic upgrade

In `plan_run` (no `requested`), when **no** resumable current-schema run exists:

- Find the newest older-schema run of this behavior with a numbered checkpoint, whose old **and**
  current schema files both exist.
- Call `brain_upgrade.upgrade_run(...)` into `next_run_id(...)` and return mode `"resume"` for it.
- Emit one service message (Vietnamese, like the other service messages):
  "Não AI được nâng cấp lên luật mới (schema v<old> → v<new>) và học tiếp từ bước <step>."
- On `UpgradeError`, or when the schema files are missing (all runs before schema 4 have none),
  keep today's behavior: a new run from zero, plus a message saying why.

Tests in `test_train_service.py` (all on `tmp_path`, with fake schema files through a patched
`SCHEMAS_DIR` and a patched `SCHEMA_VERSION` = 5):

- an old run gets upgraded and resumed;
- a missing schema falls back to new;
- an existing current-schema run is resumed as before, with no upgrade;
- the champions folder is never used as a source.
